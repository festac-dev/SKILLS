# Patterns for Projects That Stand Out

Distinctive projects share traits. Use these as prompts for ideas; select only what fits the project's truth.

## 1. A real idea expressed everywhere
One clear concept informs layout, motion, copy, sound, errors, and docs. Example directions (illustrative): *a logistics tool where the interface is a living route map; a finance tool whose numbers settle and reconcile visibly; a writing tool that treats the page like paper; a dev tool whose terminal feels like a cockpit.*

## 2. One signature moment
An interaction, transition, or graphic people describe to others. Make it exceptional, fast, accessible, and obviously connected to the product's purpose.

## 3. Show the system working
Animated graphics that reveal truth: data flowing along real pipelines, orbiting entities with real relationships, layers that separate to explain architecture, live status with meaning. Prefer motion that encodes data over decoration.

## 4. Speed as a feature
Instant navigation, optimistic UI with safe rollback, skeletons that match content, offline resilience, tiny bundles, prefetching. Perceived performance is part of "wow."

## 5. Craft in the unseen
Empty states, error recovery, loading, keyboard shortcuts, focus rings, form validation, undo, input masks, 404s, email layouts, print styles, docs, changelogs, status pages.

## 6. Typography and space
Considered type scale, rhythm, line length, numerals, alignment, density options. Excellent type makes ordinary pages feel premium.

## 7. Specific, human copy
Language drawn from users' words and the domain; no filler; confident, truthful claims.

## 8. Playful intelligence
Small delights that reward curiosity (easter eggs, thoughtful sounds, cursor behaviors) without blocking tasks or violating accessibility.

## 9. Real interactivity
Live demos, editable examples, sandboxes, calculators, explorable explanations, data playgrounds instead of screenshots.

## 10. Trust signals that are true
Transparent pricing, honest limitations, public status/uptime, security practices described precisely, real customer outcomes only with permission.

## 11. Engineering excellence as differentiation
Reliability, privacy-first design, open standards, exportability, API quality, documentation, performance budgets, accessibility conformance with evidence.

## 12. Opinionated defaults, flexible edges
A clear point of view that still respects user control and existing conventions.

## Stand-out checklist
- [ ] Can someone describe this product's feel in one sentence?
- [ ] Is there a signature moment tied to purpose?
- [ ] Does it hold up with reduced motion, slow networks, and assistive tech?
- [ ] Does every effect earn its place?
- [ ] Would the design still work if all decoration were removed? (If not, the structure is weak.)

## More prompts
Make first use fast (a working state in under a minute, sample data or guided start). Offer command palette/search and keyboard shortcuts for tool-like products. Publish a status page, changelog, and honest limits. Provide exports, API, and webhooks for portability and trust. Use `templates/STANDOUT_OPPORTUNITY_REGISTER.md` to decide what to include.

# Content Design and Voice Guide

## Principles
- Write for the user's task, not the organization's desire to sound impressive.
- Prefer concrete verbs and familiar words.
- Be specific about what happened, what is uncertain, and what the user can do next.
- Keep labels concise and consistent.
- Explain technical terms when the audience needs them.
- Never invent urgency, proof, testimonials, guarantees, or capabilities.

## Error writing
State the problem in plain language, preserve user input when safe, explain recovery, and provide a support path for unresolved issues.

## AI-assisted content
Remove generic openings, repetitive summaries, filler enthusiasm, buzzword stacks, and claims unsupported by the product. Review every generated string in its actual interface context.

## Application evidence

Check primary labels against actual destinations and outcomes. Working tools should be named for the task they perform; unavailable actions need a precise status. Avoid development commentary, unsupported scale claims and identical slogans across unrelated products.

# Product Capability Catalogue

This catalogue is a discovery aid, not a feature checklist. A capability should be selected only when justified by product purpose, user needs, risk, constraints and evidence.

## Product foundations
Accounts, identity, profiles, organizations, workspaces, roles, permissions, invitations, onboarding, preferences, help, support, notifications, search, settings, audit history and data export.

## SaaS and enterprise
Plans, subscriptions, entitlements, billing, invoices, usage, quotas, tenant isolation, SSO, SCIM, policy management, administration, compliance workflows and service health.

## AI and automation
Agent lifecycle, task planning, tool registry, scoped permissions, approvals, execution logs, traces, memory controls, evaluation, reproducibility, human review, budget controls, cancellation, retries and audit evidence.

## Developer platforms
Repositories, branches, pull requests, builds, tests, terminals, editors, API explorers, logs, metrics, traces, deployment, environments, secrets, feature flags and incident response.

## Data and analytics
Dashboards, tables, filters, saved views, charts, maps, timelines, graph explorers, data import/export, lineage, annotations and reporting.

## Commerce and finance
Catalogues, discovery, carts, checkout, payment status, refunds, invoices, subscriptions, inventory, fulfilment, reconciliation and fraud controls. Apply appropriate legal and regulatory review.

## Collaboration
Presence, comments, mentions, shared editing, approvals, assignments, activity history, conflict resolution, versioning and notifications.

## Content and creative tools
Rich-text editing, media libraries, asset management, visual canvases, timelines, version history, publishing, review and export.

## Community and communication
Feeds, messaging, groups, moderation, reporting, blocking, privacy settings, abuse handling and content controls.

## Education and services
Courses, lessons, assessments, progress, scheduling, service requests, case management and records, subject to domain-specific safety and privacy requirements.

## Infrastructure and connected devices
Fleet/device inventory, telemetry, command authorization, status, alerts, maps, maintenance, provisioning, offline sync and remote operations.

## Interface patterns
Landing pages, documentation sites, dashboards, application shells, headers, sidebars, footers, navigation, forms, tables, editors, dialogs, menus, drawers, toasts, empty states and responsive variants. None are mandatory.

## Experience layers
2D layout and information; 3D spatial depth; time-based motion; adaptive and stateful interactions; immersive or multi-sensory experiences. Use only the layers that serve the task and are technically viable.

## Application evidence

Map a selected capability to an explicit user task and an owning specialist through project routing or catalogue search. Record a missing capability as a gap only when required by the brief; unselected catalogue entries are not unfinished product work.

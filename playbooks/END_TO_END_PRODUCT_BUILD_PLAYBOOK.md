# End-to-End Product Build Playbook

## Phase 1 — Understand
Inspect the repository, product brief, users, current behavior, constraints, deployment, and existing decisions. Preserve working functionality.

## Phase 2 — Discover
Research the problem, map journeys, identify domain rules, validate assumptions, and define measurable outcomes.

## Phase 3 — Decide
Create scope, non-goals, risk register, architecture decisions, capability selection, and release slices.

## Phase 4 — Design
Design information architecture, interaction states, content, responsive behavior, accessibility, and design tokens only as needed.

## Phase 5 — Build
Implement in dependency order. Keep the application runnable. Use small changes, migrations, tests, and observable checkpoints.

## Phase 6 — Verify
Run automated and manual tests, security and privacy reviews, accessibility checks, performance checks, and realistic failure scenarios.

## Phase 7 — Operate
Prepare deployment, configuration, secrets, monitoring, alerts, backups, support, incident response, and rollback.

## Phase 8 — Learn
Review real outcomes, feedback, incidents, cost, and assumptions. Prioritize evidence-backed improvements.

At every phase: distinguish implemented, partially implemented, experimental, deferred, and unverified work.

## Application evidence

Complete the primary journey with representative data, reload its durable result and exercise a relevant failure. Verify the actual preview artifact and expose integration limitations accurately before handing over links.

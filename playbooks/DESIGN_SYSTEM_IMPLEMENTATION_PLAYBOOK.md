# Design System Implementation Playbook

## Discover
Audit existing UI, user tasks, accessibility, brand assets, platform conventions, and repeated patterns.

## Establish foundations
Define semantic tokens only where repetition and consistency justify them. Do not force a palette, font, radius, shadow, or visual identity.

## Build components
Start with high-frequency, high-impact components. Specify anatomy, variants, states, responsive rules, accessibility, and content behavior.

## Validate
Test real screens, long content, localization, themes, keyboard, assistive technology, reduced motion, and visual regression.

## Govern
Define contribution, review, versioning, deprecation, ownership, and exception policy. Avoid premature component abstraction.

## Application evidence

Review the rendered component family across populated screens, overlays and narrow layouts. For a requested redesign, verify the intended identity survives across all workspaces and states; do not stop at replacing homepage colors.

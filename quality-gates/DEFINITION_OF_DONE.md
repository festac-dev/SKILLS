# Definition of Done

A change is complete only when all applicable items are satisfied.

## Product
- [ ] Solves a defined user problem or meets an explicit requirement.
- [ ] Acceptance criteria are observable.
- [ ] Scope is justified; unnecessary features were excluded.

## Design and content
- [ ] Existing brand and design decisions are respected.
- [ ] No logo, colour, font, style, layout or effect was forced.
- [ ] Language is clear, natural and accurate.
- [ ] Relevant responsive and interaction states are handled.
- [ ] No fake controls, dead links or misleading placeholders remain.

## Engineering
- [ ] Implementation follows project conventions.
- [ ] Errors and edge cases are handled.
- [ ] No secrets or sensitive data are exposed.
- [ ] Migrations and compatibility are considered.
- [ ] Performance impact is understood.

## Accessibility and security
- [ ] Applicable accessibility checks were performed.
- [ ] Authorization is enforced at trusted boundaries.
- [ ] Sensitive data is minimized and protected.
- [ ] Risks and limitations are documented.

## Verification and release
- [ ] Relevant tests were run and results recorded.
- [ ] Build and runtime behavior were checked.
- [ ] Critical journeys were verified.
- [ ] Documentation and configuration are accurate.
- [ ] Rollback/recovery is understood where relevant.
- [ ] Unverified items are explicitly disclosed.

## Application evidence

The final evidence identifies the changed artifact, current preview status and actual user outcome. Explicitly requested visual behavior is verified in the running interface; unavailable integrations cannot be counted as complete because a fixture passed.

# Project Discovery and Scope Gate

- [ ] The problem and intended users are concrete.
- [ ] User evidence and assumptions are separated.
- [ ] Desired outcomes and baseline measures are defined.
- [ ] Constraints, dependencies, and non-goals are explicit.
- [ ] Candidate features are prioritized by value, risk, and cost.
- [ ] The smallest useful release is identifiable.
- [ ] Accessibility, privacy, security, and operational implications are considered.
- [ ] Deferred work has a reason and revisit trigger.

A complete catalogue is not a complete product. Scope is complete when the chosen scope is justified.

## Application evidence

Retain the user’s latest corrections as acceptance criteria alongside the original objective. Similar products need independent identity decisions when requested, and an added maintenance task does not silently cancel unfinished product work.

# CLI and TUI Quality Gate

- [ ] Traditional CLI and interactive modes are chosen based on task needs.
- [ ] Script/CI and non-TTY behavior are defined.
- [ ] Commands/actions have stable IDs and validated schemas.
- [ ] Help, completion, and UI discovery do not drift.
- [ ] Dynamic capabilities are discovered safely where supported.
- [ ] No arbitrary hard-coded provider/model/action list blocks extensibility.
- [ ] Keyboard-only users can complete all essential tasks.
- [ ] Mouse interactions work where supported and have keyboard equivalents.
- [ ] Focus, selection, disabled, loading, error, and success states are clear.
- [ ] Resize, narrow/short terminals, Unicode, and color fallbacks are handled.
- [ ] SSH/multiplexer latency and terminal restoration are tested.
- [ ] Long-running work is cancellable and does not block rendering.
- [ ] Destructive actions have appropriate confirmation/recovery.
- [ ] Compatibility claims are backed by tests and documented evidence.

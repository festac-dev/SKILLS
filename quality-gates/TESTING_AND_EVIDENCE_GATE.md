# Testing and Evidence Gate

- [ ] Acceptance criteria map to reproducible tests.
- [ ] Critical business invariants are tested.
- [ ] Authorization and tenant isolation are tested.
- [ ] Failure, retry, concurrency, and recovery paths are exercised.
- [ ] Accessibility, performance, security, and compatibility are evaluated as applicable.
- [ ] Test data and environments are representative.
- [ ] Flaky tests are tracked rather than ignored.
- [ ] Results include commands, environment, artifacts, and known gaps.
- [ ] Claims in release notes match verified behavior.

## Application evidence

An empty-data page, screenshot or HTTP 200 cannot prove a multi-step workflow. Include representative state and a meaningful failure, identify fixtures, and parse result artifacts when their contents matter.
